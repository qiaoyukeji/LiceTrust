# 敏捷开发计划与实施记录（AGILE.md）

本项目依据《正版软件管理平台 需求分析与设计文档》（V1.0 征求意见稿）采用**敏捷开发**方式实施。
本文档记录 Sprint 规划、Backlog、用户故事、完成的定义（DoD）与实际交付对照，可作为后续迭代的滚动计划基线。

## 1. 敏捷框架与团队

- **框架**：Scrum（双周迭代），每日站会 15 分钟，迭代评审 + 回顾各 1 次/Sprint
- **角色映射**：
  - Product Owner：需求文档编制单位（信息化主管部门）
  - Scrum Master：平台架构师（本仓库规范手册与代码生成器的维护者）
  - 开发团队：按模块分工（系统基础组 / 台账资产组 / 流程报表组 / 前端 PC 组 / 移动端组）
- **需求管理**：设计文档 4.4 的 FR-xx-xx 编号即用户故事编号；P0 必做、P1 重要、P2 可选

## 3. 用户故事示例（Sprint 4）

- **US-FR-08-01**（P0）：作为普通员工，我可以在线填报《软件安装维护申请表》并提交审批，以便合规地申请软件安装。
  - 验收：选择本人计算机、申请类型（安装/卸载/升级）、软件名称版本、原因；提交后状态=待部门审核；全程留痕可查。
- **US-FR-08-02**（P0）：作为部门负责人，我可以审批本部门的安装申请（通过/驳回+意见），以便把好第一道关。
  - 验收：仅能看到本部门申请（数据权限=3）；审批记录含审批人与时间。
- **US-FR-08-05**（P0）：作为系统，申请确认后应自动写回安装明细台账，保证账实相符。
  - 验收：安装→新增明细；卸载→明细逻辑删除；升级→版本更新且分别登记"升级前卸载/升级后安装"两条维护日志。

## 4. 完成的定义（Definition of Done）

1. 功能实现并覆盖对应 FR 验收标准（设计文档 4.4.x 表格）
2. `node --check`（后端）/ `vite build` 零错误（前端）通过
3. 通过全端点冒烟测试（server/scripts/smoke.js，含 RBAC 与数据权限负向用例）
4. 安全要求满足：零手写 SQL（参数化生成）、敏感字段 AES-256-GCM 加密+脱敏、写操作审计留痕
5. 中文注释标注需求编号，代码符合 docs/BACKEND-CONVENTIONS.md / FRONTEND-CONVENTIONS.md

## 5. 质量门禁与测试策略（对应设计文档 10.2）

- **功能**：smoke.js 覆盖 24 个模块 64 项断言（登录/列表/详情/流程闭环/预警/报表导出）
- **数据一致性**：安装数量由明细实时聚合（查询子查询），许可数量由授权聚合，报表"表表相符、账账相符、账实相符"由同一数据源保证
- **权限**：RBAC 功能权限点 + 数据权限（1全部/2本单位/3本部门/4仅本人）；smoke 含越权 403 与数据隔离断言
- **安全**：Mimosa 安全扫描全过程拦截写操作（SQL 注入/路径穿越/弱加密等规则），全部按"字面量 SQL + 参数绑定 + 白名单校验"合规模式整改
- **报表格式**：exceljs 导出回读校验（冒烟含二进制头与字节数断言）
- **兼容性**：PC 端 Chrome/Edge；移动 H5 响应式；不依赖特定 OS
